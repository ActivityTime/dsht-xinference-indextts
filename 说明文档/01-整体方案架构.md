# 01 · 整体方案架构

> 本地动漫角色 TTS（IndexTTS-2.5 + Xinference）架构说明 · 2026-10-24
> 配套可视化：`整体方案架构图.html`

---

## 一、需求基线（用户拍板的硬口径）

| 项 | 要求 |
|---|---|
| 用途 | **本地自用**，授权无所谓 |
| 部署 | 本机本地，非云端；只关心三项核心能力 |
| 核心能力① | **零样本克隆**（任意角色给参考音频即出声，免训练） |
| 核心能力② | **无需逐字稿**（只传参考音频 + 文本，不要参考文字转录） |
| 核心能力③ | **情绪控制**（可定量/可描述，非焊死在参考音频里） |
| 语种 | 中 / 日 / 英（IndexTTS-2.5 还多西/阿） |
| 本机硬件 | RTX 3080 10GB，接受 bf16 |

## 二、为什么是 IndexTTS-2.5（引擎选型结论）

按三项核心能力逐引擎过滤，只有 **IndexTTS-2.5 三项全中**：

| 引擎 | 零样本克隆 | 免逐字稿 | 情绪控制 | 结论 |
|---|---|---|---|---|
| **IndexTTS-2.5** | ✅ 3–10s 参考音频 | ✅ `prompt_speech` 免转录 | ✅ 8维向量/文本/音频，音色-情绪解耦 | **主选** |
| Qwen3-TTS | 克隆需参考文本 | ❌ | 克隆与情绪互斥 | 淘汰 |
| CosyVoice 3.0 | 零样本必须传 prompt_text | ❌ | instruct 文本 | 淘汰 |
| Fish Speech S2 | 克隆必配参考文本 | ❌ | 一般 | 淘汰 |
| F5-TTS | 参考音频要配文本转录 | ❌ | — | 淘汰 |
| Chatterbox Multilingual | — | — | 情绪=夸张度放大 | 仅备选 |
| OmniVoice | 克隆 + voice design | 有 | **无情绪轴** | 出局 |

IndexTTS-2.5 技术要点：
- **Code 架构**，0.8B GPT backbone，五语 `ZH/EN/JA/ES/AR`
- **音色-情绪解耦**：音色存 `feat1.pt`、情绪存 `feat2.pt`，完全独立（可用 A 音色演绎 B 情绪）
- 情绪控制三种方式：`emo_vector`（8 维定量）、`emo_audio_prompt`+`emo_alpha`（取 A 音色 B 情绪音频）、`emo_text`+`use_emo_text`（自然语言）
- 授权：bilibili Model Use License；月活<1亿且年营收<10亿免费商用 → **个人自用完全没问题**

## 三、为什么用 Xinference 当底座（载体选型结论）

IndexTTS-2.5 官方 README **只提供 WebUI + Python 推理 API，不提供 OpenAI 兼容 HTTP 服务**。社区事实标准底座为 **Xinference**：

| 底座 | 结论 |
|---|---|
| **Xinference 4.0.1** | ✅ 社区事实标准；`/v1/audio/speech` OpenAI 兼容；`prompt_speech` 只传参考音频免逐字稿；`emo_vector/emo_text/emo_alpha/use_emo_text` 全直通 |
| vLLM-Omni | 偏 Linux / 重，Windows 不便 |
| OpenTalking | 捆绑数字人框架，非纯 TTS |
| 社区 WebUI 整合包 | 无 OpenAI 兼容接口，难接 DSH-Tavern |

## 四、分层架构

```
┌─────────────────────────────────────────────────────────────┐
│ 消费层   DSH-Tavern（Provider Endpoint → http://127.0.0.1:9998/v1）│
└──────────────────────────────┬──────────────────────────────┘
                               │ POST /v1/audio/speech（multipart）
┌──────────────────────────────▼──────────────────────────────┐
│ 服务层   Xinference 4.0.1                                     │
│         xinference-local --host 127.0.0.1 --port 9997        │
│         鉴权关闭 · 就绪超时 180s · 探测 /status               │
│         转发 prompt_speech / emo_vector 等参数到模型          │
└──────────────────────────────┬──────────────────────────────┘
                               │ RESTfulClient.launch_model(use_bf16)
┌──────────────────────────────▼──────────────────────────────┐
│ 模型层   IndexTTS-2.5（bf16 加载，RTX 3080 10GB）            │
│         T2S(自回归) → 语义token → S2M(Zipformer) → BigVGAN2   │
└──────────────────────────────┬──────────────────────────────┘
                               │ spk_audio_prompt（参考音频 3–10s）
┌──────────────────────────────▼──────────────────────────────┐
│ 资产层   参考音频库 I:\...\prompt                             │
│         datealive/ja 1047段 · genshin · kurisu · ...          │
└─────────────────────────────────────────────────────────────┘
```

**环境层**：独立 venv `<部署根>\venv`（Python 3.13），torch/torchaudio/torchvision 2.11.0+cu128（CUDA 12.8，sm_86）。

## 五、数据流（一次合成请求）

1. **DSH-Tavern** 按角色绑定音色，发 `POST /v1/audio/speech`（multipart）：
   - 文件字段：`prompt_speech`（该角色的参考音频 wav）
   - 表单字段：`model=IndexTTS-2.5`、`input=<台词文本>`、`voice`、`response_format`、`speed`
   - JSON 字符串字段：`kwargs`（可含 `lang`、`emo_vector`/`emo_text`/`emo_alpha`/`use_emo_text`）
2. **Xinference** 收到后直通到 IndexTTS，调 `infer(spk_audio_prompt, text, lang, emo_vector, duration_factor, ...)`。
3. **IndexTTS**：文本→G2P→T2S→语义token→S2M→Mel→BigVGAN2 声码器→22.05kHz wav。
4. 音频返回 DSH-Tavern，按台词内容 hash 缓存在插件 `speech-cache/`（重复台词不重复合成）。

> 关键实证：**只传 `prompt_speech`（参考音频）+ 文本即可，无需逐字稿**（实测确认）。

## 六、关键参数

| 参数 | 值 / 说明 |
|---|---|
| 语种 `lang` | `ZH / EN / JA / ES / AR` |
| `emo_vector` | 8 维 `[happy,angry,sad,afraid,disgusted,melancholic,surprised,calm]`，每维 0–1 |
| `emo_text` + `use_emo_text` | 自然语言描述情绪（需另挂 QwenEmotion，省资源优先用 vector） |
| `emo_audio_prompt` + `emo_alpha` | 音色取 A、情绪取 B 音频 |
| `duration_factor` | 0.5–2.0 语速控制 |
| `prompt_speech` | **必传**（3–10s 干净参考音频），免逐字稿 |

---

## 七、显存（VRAM）仲裁

- 本机 RTX 3080 **10GB 总显存**。
- IndexTTS-2.5 bf16 ~6GB；若并跑 OmniVoice（~3–4GB）会超 10GB。
- 原选型结论定的规则：**谁用谁加载，另一个卸载**（`del _model; torch.cuda.empty_cache()`）。
- 当前方案直接用 Xinference 跑 IndexTTS，未并行 OmniVoice；若将来要双引擎切换，按此仲裁。
