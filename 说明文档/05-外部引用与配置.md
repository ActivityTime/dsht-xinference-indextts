# 外部引用与配置（Xinference · 配置化改造 2026-10-24）

> 规则：**内部路径一律相对 `config.ps1` 定位，禁止绝对路径；外部引用环境在此明文列出。**

## 一、配置化规则

- 中央配置：`<部署根>\config.ps1`（必须与 `start_xinference_indextts.ps1` 同目录，被 dot-source）。
- **内部路径**（venv / .xinference / launch / test 脚本）由 `config.ps1` 基于自身所在目录**相对计算**，不写任何绝对路径。
- **外部引用**在 `config.ps1` 的 `$Script:ExternalDeps` 明文列出（下表）。
- 环境变量（`XINFERENCE_HOME` / `HF_*` / `XINFERENCE_ENDPOINT` / `MODEL_NAME` 等）由 `config.ps1` 统一注入，各脚本只读取不硬编码。

## 六、库音频引用格式（🔴 硬规范：禁止用序号）

参考音频库里的每条音频，在**配置框**与**正文内联指令**中各有一种引用格式。**两种都以「库名」开头，绝不允许用 int 序号**。

| 场景 | 格式 | 示例 | 贴到哪里 |
|---|---|---|---|
| 配置框（voice / 引导音频 / 情绪映射音频） | `库名\|相对路径` | `默认音色库\|_ab_indexTTS/clips/甘雨/zh_Ganyu_0003_平静_疑问询问.wav` | 控制台各配置框 |
| 正文内联指令 | `库名/相对路径`（斜杠） | `#[音色选择][默认音色库/_ab_indexTTS/clips/甘雨/zh_Ganyu_0003_平静_疑问询问.wav]` | 适配层请求正文 / DSHT 台词 |

**为什么必须用库名**：`0`、`1` 这类序号是**库源在 `library.json` 里的排列位置**。一旦增删或调整库源顺序，全部历史引用集体错位——引用的音频会静默变成别的文件（音色错乱、引导音频失效），且没有任何报错。库名唯一、语义稳定，重排不影响。

**兼容策略**（服务端 `_resolve_lib_root` / `_ref_from_piped`）：

- 优先按**库名**匹配；
- 老配置/外部脚本粘贴的**旧序号格式仍可用**，但会带「索引引用（旧格式，重排库源会失效，保存后自动迁移为库名）」降级提示；
- 非法库名 → 明确报错「库源名不存在: X」；序号越界 → 「库源索引越界: N」。

**自动迁移**：所有配置在**保存时**自动把序号格式改写为库名格式（`_migrate_audio_ref` / `_migrate_piped_ref`）。已存在的历史配置可用一次性脚本迁移：

```powershell
downloads\venv-main\Scripts\python.exe scripts\migrate_refs_to_rootname.py
```

（脚本幂等；迁移前会在 `console/_backup_before_rootname_migration/` 留回滚点。）

**获取路径**：控制台「参考音频库」每个条目旁有四个按钮——「复制名」（得 `库名|相对路径`）、「复制音色指令」/「复制情感指令」（得可直接贴进正文的内联指令）、「用作参考」（回填合成页）。

## 七、整体搬文件夹步骤

1. 移动整个 `<部署根>` 到新位置（venv 与 `.xinference` 相对结构自包含，可直接搬）。
2. 改 User 级 `XINFERENCE_HOME` 指向新位置下的 `.xinference`（或用脚本启动则自动重算，可不动）。
3. **无需改任何脚本**（内部路径全部相对 `config.ps1` 自动适应）。
4. 前提：目标机必须存在 ① 同版基础 Python 3.13；② NVIDIA 驱动（sm_86）；③ MSVC 运行库——否则 venv 无法启动。
