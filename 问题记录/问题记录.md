## 1. torch 导入报 `PermissionError: [WinError 5] 拒绝访问`

**现象**：新 venv 里 `import torch` 加载 `torch_python.dll` 被拒。

**根因**：`C:\Windows\System32` 整套 MSVC / OpenMP / Concurrency 运行库 **ACL 损坏**（CONCRT140、MSVCP140_1、MSVCP140_2、MSVCP140_atomic_wait、MSVCP140_codecvt_ids、VCOMP140 等连读取都被拒，icacls 也读不出 ACL）。VCOMP140 本身正常（早期 VoiceStudio 工单已修过），真凶是其余 DLL。

**修复**：提权执行 `takeown + icacls reset + grant` 逐个修复。

**插曲**：两次提权"白跑"——修复脚本第 19 行引号笔误 `"[== $d =="]`（少收尾 `]`），整脚本解析失败。修正后提权执行成功。

## 2. CUDA torch 换装（CPU 版不能用）

**现象**：默认 `pip install xinference` 装的是 **CPU 版 torch**（`cuda=False`），RTX 3080 用不了。

**根因**：cu128 索引最高只有 **torch 2.11.0**（CPU 版 2.14.1 是另一条线，无 cu128 2.14.1）。

**修复**：
- 官方源 `download.pytorch.org/whl/cu128/` 的 2.75GB 大轮经 **pip 下载停滞**（10 分钟无增长）→ 改用 **curl 直连**（实测 14-15MB/s，~3 分钟）。
- **阿里云 `mirrors.aliyun.com/pytorch-wheels/cu128/` 无 Windows cp313 win_amd64 轮**（`/torch/` 404，目录里也没有），不可用。
- **wheel 文件名被截短**（如 `...-cp313-win`）导致 pip 报 `Invalid wheel filename (wrong number of parts)` → 改回标准全名（`cp313-cp313-win_amd64`）后 `pip install --force-reinstall --no-deps` 本地安装成功。
- 最终：`torch 2.11.0+cu128 / torchaudio 2.11.0+cu128 / torchvision 0.26.0+cu128`，`cuda_available=True`，RTX 3080 (8,6)=sm_86 ✓。

## 3. Xinference 服务起不来：`RuntimeError: Cluster is not available after multiple attempts`

**现象**：`xinference-local` 启动 ~10s/66s 后退出，health 连不上。

**根因（三层，全部要改）**：
1. **`--host 0.0.0.0` 导致内部 health_check 连不上子进程**：xinference 的 supervisor/worker 绑定 `0.0.0.0:随机端口`，父进程 `health_check` 用字面 `0.0.0.0:端口` 去 `xo.actor_ref` 连接（Windows 上连 0.0.0.0 失败）→ **改用 `127.0.0.1`**（本地自用足够）。
2. **子进程就绪等待默认 10s 太短**：xinference-local 会拉起 supervisor/worker 子进程，首次启动要 **~50-90s**（导入 torch + CUDA 初始化 + GPU orphan 扫描 20+ 进程）才发 READY；父进程超时退出时把 daemon 子进程带走。→ 设 **`XINFERENCE_HEALTH_CHECK_TIMEOUT=180`**（实测 ~51s 就绪）。
3. 调大后仍失败（连 0.0.0.0 的问题叠加）——把 127.0.0.1 + 180s 一起改后通过。

## 6. `xinference launch` CLI 无法传 `use_bf16`

**现象/原因**：`xinference launch --help` 无 `use_bf16`/`--model-config` 选项，无法让 IndexTTS-2.5 以 bf16 加载。

**修复**：用 **Python 客户端** `RESTfulClient.launch_model(model_config={"use_bf16": True})`（`**kwargs` 原样并入 payload）。已封装 `launch_indextts.py`。

## 7. IndexTTS-2.5 权重精度说明

- **下载**：官方全精度 `IndexTeam/IndexTTS-2.5`（HF，约 6GB）。**无量化版本**（管线无 int8/int4/GGUF）。
- **运行时**：默认 fp32（`use_bf16=False`）；设 `use_bf16=True` 时**加载时 cast 成 bf16**（内存优化，非真量化）。RTX 3080 10GB 建议 bf16。

## 9. ModelScope 下载 w2v-bert-2.0 收尾崩溃（WinError 183/32）

**现象**：IndexTTS-2.5 权重几乎下完（GPT/codec/s2mel 已加载），最后卡在 w2v-bert-2.0：`FileExistsError [WinError 183] 当文件已存在时，无法创建该文件 ... \hf_cache\w2v-bert-2.0\.msc` → 接着 `PermissionError [WinError 32] 另一个程序正在使用此文件` → 整个 launch 失败，脚本误回退去拉旧模型 IndexTTS2。

**根因**：w2v-bert-2.0 走 **ModelScope**（HF 直连不可达时 IndexTTS 自动映射到 ModelScope）。ModelScope 在 Windows 上把临时文件重命名成完成标记 `.msc` 时，因 `.msc` 已存在（上次残留）报 WinError 183，随后访问被占用的 `.msc` 报 WinError 32。

**修复**：权重其实已下完（`conformer_shaw.pt` 2.2GB + `model.safetensors` 2.2GB 都在，`.msc` 也已存在）→ **直接重拉 launch**，这次 w2v-bert 被判定完成、跳过，模型顺利加载。

**教训**：①launch 脚本的"IndexTTS2 回退"要默认关闭（`ALLOW_FALLBACK=0`），否则失败会误下 5.6GB 旧模型 + QwenEmotion；②重下前先检查缓存是否其实已完整。

## 13. `/v1/audio/speech` 实测踩坑

1. **shell 里给 curl 传 `kwargs` JSON，双引号被剥掉** → 服务端 `json.loads(kwargs)` 报 `Expecting property name enclosed in double quotes (char 1)`，HTTP 500。**改用 Python `requests` 发 multipart**（`K:\SomeApps\Xinference\tts_test.py`），彻底绕开 shell 引号问题。

3. **IndexTTS 必须有 `prompt_speech`**（无默认音色），只传参考音频 + 文本即可（免逐字稿确认）。
4. **emo_vector 顺序**：`[happy,angry,sad,afraid,disgusted,melancholic,surprised,calm]`。

## 16. 重复模型实例累积 → 显存/内存打满（bug 修复，2026-10-24）

**现象**：分析内存/磁盘占用时，`/v1/models` 有 **2 个 IndexTTS-2.5 实例**（`IndexTTS-2.5` + `IndexTTS-2.5-Y2E4CfSK`）：GPU 显存 9.5/10GB（free 仅 486MB）、系统内存 15.9GB 仅剩 1.1GB。磁盘 IO 空闲态为 0（磁盘侧正常）。

**根因**：每次运行 `start_xinference_indextts.ps1` 都会 `launch` 一个**新实例**（uid 带随机后缀 `-XXXX`），旧实例不卸载 → 叠加累积占满显存/内存。**属 bug，需遏制。**

**修复**：`scripts\launch_indextts.py` 改为**幂等加载**——launch 前先 `list_models()` 命中 `model_name` 则**复用**（跳过 launch），不重复建实例；fallback 到 IndexTTS2 时同样先查。

**处置**：卸载多余实例 `IndexTTS-2.5-Y2E4CfSK`（保留 DSH 使用的 `IndexTTS-2.5`），GPU 显存由 9.5GB 降至 **2.8GB**（释放 ~6.7GB），系统可用内存 1.1→2.0GB。

**验证**：模型已在运行态跑 launch 脚本输出 `already running as uid=IndexTTS-2.5; reuse (skip launch)`，`/v1/models` 实例数保持 1。

**长期约束**：①启动/加载脚本幂等（已修）；②物理内存 16GB 偏小，Xinference(~5GB)+豆包/壁纸/Edge 常驻会吃紧，合成时尽量关多余 GPU 进程。

## 17. IndexTTS-2.5 内存优化（加载参数 + 推理流程，2026-10-24）

**问题**：服务物理 RAM ~5GB（模型子进程 WS 5022MB）。根因：IndexTTS-2.5 是 **8 组件级联**（qwen0.6b + w2v-bert + codec + s2mel + campplus + bigvgan + emo/spk matrix），加载时组件先在 CPU 整份载入再搬显存，**CPU 权重副本残留**（尤其 w2v-bert fp32 2.16GB）+ torch 内存池不归还 → WS 5GB。

**优化补丁**（改 Xinference 代码，**升级会被覆盖需重打**；原文件备份 `logs\backup\`）：
1. `xinference/thirdparty/indextts/infer_v2_5.py`：w2v-bert（Wav2Vec2BertModel）、bigvgan 加载加 `low_cpu_mem_usage=True`；semantic_model 转 `.bfloat16()`。
2. `xinference/model/audio/indextts2.py`：`speech()` finally 加 `torch.cuda.empty_cache()`（低频单用户适用；高频循环需移除）。

**效果（实测）**：模型子进程 WS **5022 → 2652MB**（省 ~2.4GB RAM）；推理功能正常（合成 HTTP 200）。

**显存实测修正**：8 组件级联模型**本体常驻显存 ~8GB**（多数组件 fp32，仅 gpt/semantic_model bf16）；此前"空闲 2.8GB"是模型重启**过渡态误判**，非稳态。empty_cache 只清推理缓存，不清模型本体。

**后续可优化（未做，有推理质量风险）**：把 s2mel / bigvgan / codec / campplus 组件全转 bf16，显存可再省 ~4GB；需逐组件验证合成质量。

## 19. 移除 IndexTTS2（旧版）及与 Xinference 的关联（2026-10-24）

**目的**：只保留必要模块（IndexTTS-2.5），移除用不到的旧版 IndexTTS2（infer_v2）在 Xinference 中的支持。

**探查**：IndexTTS2 家族注册在 `xinference/model/audio/indextts2.py`（`Indextts2` class），经 `core.py` 的 `model_family=="IndexTTS2"` 映射；类内用 `model_spec.model_name=="IndexTTS-2.5"` 分新旧分支：
- **v2_5 分支**（IndexTTS-2.5，本项目用）：走 `indextts.infer_v2_5`（8 组件级联，含 #17 优化）；
- **旧版分支**（IndexTTS2，用不到）：走 `indextts.infer_v2`，`load()` 第 125 行起 + 组件加载**全为旧版专用**；
- `scripts/launch_indextts.py` 含 `ALLOW_FALLBACK`（默认关）→ IndexTTS2 回退路径。

**变更（每步）**：
1. 备份 `indextts2.py`、`launch_indextts.py` → `logs\backup\indextts2.py.orig2`、`launch_indextts.py.orig2`。
2. `indextts2.py` `load()`：v2_5 分支 `return` 后插入 `raise ValueError("IndexTTS2 (legacy) support has been removed; only IndexTTS-2.5 is supported.")`，使旧版分支**不可达**（代码保留，可回滚）。
